# 小程序界面优化

## 设计方向

面向在家做饭的用户，用菜单式清单查菜、用完整菜谱备料，再进入蓝图或单步跟做。视觉沿用 H5 中名为「典藏」的 `paper` 主题，将用户提到的“经典”理解为这套现有配色。

- 象牙纸色：`#fbf6eb`，内容表面：`#fffcf5`。
- 墨色：`#2a221a`，正文：`#3b3127`。
- 酒红：`#7a2e26`，哑金：`#a7843f`，细线：`#ddd0b4`。
- 蓝图采用 H5 典藏画布 `#ece2cb`、节点纸色 `#fffcf5`、深蓝灰/酒红/金棕标题；食材连线与引脚使用 H5 的色相分配，工具统一蓝色。
- 气质为温暖、沉稳、易读；章节编号和步骤序号作为统一细节。

## 原界面问题

1. 首页每张卡片重复“查看做法”，减少同屏可比较的菜谱。
2. 无图占位区域没有提供备料或烹饪信息，却占据详情首屏。
3. 绿色阅读界面与深色蓝图割裂，功能切换缺少一致感。
4. 跟做页提示重复，当前步骤、原料和操作按钮的层级不够清楚。
5. 搜索缺少清除与空结果恢复入口。
6. 浏览器适配存在页面选择器误替换、原生自闭合 progress 被当作 HTML 容器的问题，影响界面评估。

## 优化内容

| 层面 | 调整 |
| --- | --- |
| 间距 | 按 8rpx 网格统一页面、章节和清单留白；底部操作避开安全区域 |
| 配色 | 统一 H5 典藏色；强调色用于选中项、主操作与步骤语义 |
| 图标 | 搜索使用简单线形图案，清除按钮保留可读标签；不增加装饰图标 |
| 文案 | 去掉重复入口和技术性验证提示；空结果可恢复到全部菜谱 |
| 字体 | 统一加载微信内置 WeChatSansStd，不支持时使用系统字体，不打包字体 |
| 布局 | 首页改为编号菜单清单；详情按备料、步骤、小记组织；跟做突出当前步骤 |
| 细节 | 原料名称和用量左右对齐，去除用量中重复名称；功能栏固定显示选中状态 |
| 视觉 | 菜谱清单与真实蓝图承担信息表达；移除无图占位，不添加装饰图片 |
| 动效 | 不增加入场动画，保留直接切换、拖动与缩放，按压仅改变透明度 |

保留「菜谱 / 跟做 / 蓝图」三个功能页、分享路径、本机跟做进度和原料关联。跟做页不展示“其余原料与工具”。完整原料清单仍在菜谱页。

## 验证范围

完成本地构建、数据/导航/进度及蓝图布局校验、Web 类型检查，以及微信官方编译与二维码生成。浏览器适配仅验证排版和普通交互；SVG 连线显示、微信内置字体、触摸手感及 iOS/Android 长文本需真机验收。

工作流程参考 unslop by Damir Sokolovsky（https://heydamir.design/unslop，CC BY 4.0）；配色与产品内容来自本仓库 H5。
