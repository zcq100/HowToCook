# 赛博菜谱 · 原生微信小程序

原生 WXML / WXSS / TypeScript，独立于 Web 构建。当前从仓库 Markdown 打包全部 **373 道菜谱、10 个分类**，不打包或下载菜谱图片。

## 构建与导入

```bash
cd miniprogram
npm ci
npm run build
npm run verify
```

在微信开发者工具导入 `miniprogram/`，读取 `project.config.json`，以 `dist/` 为运行根目录。TypeScript 已在本地编译，不需要工具再次编译 TS 或构建 npm。修改后重新执行 `npm run build`。

AppID 为 `wx5b929ed10b5ccafc`。真机预览和上传需要相应权限；个人工具配置保存在已忽略的 `project.private.config.json`。

## 数据与包体

- `scripts/build-data.mjs` 遍历 `dishes/` 中所有菜谱 Markdown，排除 `template/` 和 `index.md`，复用 Web 解析函数生成 `src/data/recipes.ts` 和 `manifest.json`。
- 构建不依赖 Web 的已生成 JSON，不触发 Web 构建或 LFS 图片下载。输出清除图片引用，`images` 为空、`cover` 为 null；不复制原始菜谱目录、照片、Web 字体和缓存。
- 数据以紧凑 JSON 字符串保存，避免 TypeScript 将全量对象展开为较大的缩进代码。全部文本本地可用，列表按页显示；分类和搜索结果显示实际总数。
- 编译前清理 `build/`，防止已删除的样本模块残留。`dist/` 仅包含运行代码与 JSON/WXML/WXSS。
- `npm run verify` 将全部生成 ID 与源 Markdown 对比，并遍历所有分页验证详情、图片排除、蓝图布局、导航及跟做进度；同时检查 1.5 MiB 内部包体预算。上传限制以微信官方编译结果和工具包分析为准。
- `packages/recipe-core/types.ts` 为共享类型；`services/repository.ts` 统一分类、列表、搜索和详情访问，后续可替换为远程 API。正式远程构建应排除本地全量数据。

## 页面

首页标题为「赛博菜谱」，直接从搜索开始；分类筛选自动换行、全部显示。菜品行仅显示名称和颜色难度图标，不展示简介及分类标签。

打开菜谱后按「菜谱 / 跟做 / 蓝图」切换，共享同一菜谱 ID。切换替换当前页面，避免返回栈增长；每个功能页可独立分享。

- **菜谱**：对齐 H5 典藏布局，双线菜单卡、居中菜名与元信息、点线原料表、独立工具说明、连续编号操作与附加内容。不显示菜谱来源和复制原文链接。
- **跟做**：分段进度、双线步骤卡、大字正文、侧线备注、参考时长、当前原料标签和底部翻页。普通按钮显示“下一步”，最后一步显示“完成这道菜”。不显示其余原料与工具。进度和完成状态保存在本机，支持重新开始；无云同步，尚未移植备料勾选、计时、常亮和朗读。
- **蓝图**：原生节点配合本地生成的 SVG 连线图片层，沿用 H5 纸色、蓝灰/酒红/金棕标题和食材色相规则。先测量节点再布局；连线区域与节点共用变换并限制图层高度，支持拖动、双指缩放、步骤关联高亮及翻步定位。菜名位于微信标题栏，底部只有一排操作，不显示操作说明或缩放/定位按钮。

用量是整道菜参考量，分次使用以步骤为准。原料与步骤的关联由启发式解析生成，未关联的原料仍可在菜谱完整清单及蓝图底部查看。

界面通过 `wx.loadBuiltInFontFace` 加载微信内置 `WeChatSansStd`（基础库 3.7.9 起），不提供字体文件；失败或不支持时回退系统字体。字体加载不会阻塞蓝图连线初始化。

## 浏览器预览


打开 `http://127.0.0.1:8766`。适配器加载原生页面逻辑、模板、样式和本地数据，支持列表、菜谱、跟做及蓝图预览。微信分享、内置字体和真机触摸效果以微信环境为准。`preview/` 不会打包。

## 官方 CI 手机预览与上传

管理员在微信公众平台「开发管理 → 开发设置 → 小程序代码上传」下载上传密钥，将执行机器的公网出口 IP 加入上传白名单。

默认密钥路径为 `miniprogram/.secrets/private.wx5b929ed10b5ccafc.key`；也可设置 `WECHAT_PRIVATE_KEY_PATH`（相对路径以 `miniprogram/` 为基准）。需要代码上传密钥文件，不是 AppSecret。密钥目录、`.key` / `.pem` 和二维码产物已忽略。

```bash
npm run wx:check
npm run wx:preview
```

`wx:check` 仅做本地检查。`wx:preview` 构建、校验后生成 `artifacts/preview.jpg`，有权限的手机微信扫码体验。Node 25 的 Web Storage 兼容参数由脚本自动处理。

上传开发版本时单独执行：

```bash
WECHAT_VERSION=0.1.0 npm run wx:upload
```

上传成功后可在公众平台设为体验版并管理体验成员；此命令不提交审核或正式发布。参考：[微信官方 miniprogram-ci](https://github.com/wechat-miniprogram/miniprogram-ci-dist)。

## 人工验收

1. 确认首页全部分类换行可见，总数与清单一致；滚动加载后能访问末页。
2. 分类与食材搜索组合筛选，检查总数、空结果、清除及恢复全部菜谱。
3. 抽查不同分类的长原料、长步骤和无用量项目；菜谱底部不出现来源入口。
4. 三个功能页反复切换，确认菜谱不变；跟做进度能恢复，完成后可以重新开始。
5. 蓝图检查首屏连线、接头、拖动边界、缩放和翻步定位；未关联原料仍可找到。
6. 真机分享进入正确功能页，断网重启仍能搜索和阅读全量文本。
7. 包分析确认没有照片或旧样本模块。浏览器不能代替 iOS/Android 真机验收。

菜谱菜单卡和跟做步骤卡的正文、原料用量、备注及内容标题单独使用 `--font-reading` 衬线字体栈；导航、按钮与其他界面仍使用微信内置字体。此设置不提供或下载字体文件，中文宋体能否实际显示取决于设备和微信可访问的本机字体；缺字或不可用时由系统回退。

首页分类筛选沿用 H5 典藏侧栏的深棕底、米色字与边框、哑金选中态。`scripts/build-category-icons.mjs` 直接从 `web/src/categoryIcons.tsx` 生成全部 11 个分类图标的普通/选中 SVG Data URL，不打包 React，不下载图片；分类保持换行、全部可见。
